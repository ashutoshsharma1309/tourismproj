## What WAS measured: the verifier

The harness has two modes, and the distinction is the whole point.

| Mode | Measures | Requires a key |
|---|---|---|
| **Fixture** | The **verifier** — does it accept what it should and reject what it should? | No |
| **Live** | The **model** — how often does it write supportable prose? | Yes |

Fixture mode measures nothing about any model. It runs prose a model plausibly *would* produce against the verifier and checks the verdict is correct.

### Fixture results — the ten required cases

Against a three-claim set (Rumtek founded 1966 by the sixteenth Karmapa; Rumtek is the seat of the Karma Kagyu lineage in exile; Losar marks the Tibetan new year):

| # | Case | Expected | Got | Rejection reason |
|---|---|---|---|---|
| 1 | Fully supported historical narrative | accept | **accept** | — |
| 2 | Supported cultural narrative | accept | **accept** | — |
| 3 | Unsupported connective statement | reject | **reject** | `no-supporting-claim` |
| 4 | Unsupported date ("rebuilt in 1992") | reject | **reject** | `unsupported-assertion` |
| 5 | Unsupported superlative ("largest in the Himalayas") | reject | **reject** | `unsupported-assertion` |
| 6 | Contains practical information ("opens daily at 6am") | reject | **reject** | `practical-data` |
| 7 | Uses a conflicting claim ("founded around 1710") | reject | **reject** | `no-supporting-claim` |
| 8 | Plausible hallucination ("400 followers from Tsurphu") | reject | **reject** | `unsupported-assertion` |
| 9 | Harmless descriptive language | accept | **accept** | — |
| 10 | Multiple claims in one sentence | accept | **accept** | — |

**Verifier accuracy: 10/10 (100%).**

Case 8 is the most informative. The sentence is entirely plausible, closely resembles the claim it is built on, and adds one detail — *"who had travelled from Tsurphu with 400 followers"* — that no claim supports. This is exactly the failure a similarity score would wave through, and it is rejected on the unsupported number and entity.

Case 7 confirms the conflict path: the compromise date 1710 appears in no claim, so it cannot verify. The pipeline additionally never puts conflicted claims in front of a model, so this sentence should not arise in the first place — the fixture proves it would be caught even if it did.

### What this does and does not tell us

**It tells us** the verifier's decision boundary is correct on cases chosen to be adversarial: it does not reward plausibility, does not accept paraphrase-plus-one-fact, and applies the practical-data firewall ahead of everything else.

**It does not tell us** how often a real model produces supportable prose. That number — the survival rate — is the honest measure of whether generative narrative earns its cost, and it remains unmeasured.

## The evaluation harness

`scripts/research/evaluate.mjs`, run via `npm run research:evaluate [-- --live]`.

Live mode records, per destination: model calls · total sentences · accepted · rejected · rejection breakdown (practical / unsupported / grounding / no-content / other) · survival rate · unsupported-assertion rate · average latency · input and output tokens · estimated cost.

Token counts come from `response.usage` captured on the provider (`lastUsage`), never estimated. Cost uses `claude-opus-5` pricing — $5 per million input tokens, $25 per million output — and is reported as `null` when usage was not returned rather than being guessed.

**The harness does not tune the verifier.** It imports it and never modifies it. If a model scores badly the correct response is to report the number: a verifier adjusted until the generator passes measures nothing at all. `qa:publishing` asserts this property.

## Which provider produced the pilot content

All Phase 5 pilot content was generated by the **deterministic `rule-based` provider**, which restates approved claims rather than composing new prose. Its output verifies at 100% by construction, so *that* number is not evidence about a model either — it is a control confirming the pipeline does not reject its own valid input.

Every published narrative block records `generatedBy`, so the provenance of any block is inspectable.
