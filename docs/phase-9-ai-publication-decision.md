# Phase 9 — AI Publication Decision

# AI NOT PUBLISHED

**Classification: CASE D — real model validation blocked by credential availability.**

---

## The decision, stated plainly

No AI-generated narrative is published in TerraStory, and none should be until the generator has been measured.

This is not a judgement that the model is bad. It is the absence of any evidence that it is good, and a product whose entire premise is *"every claim traces to a source"* cannot ship an unmeasured generator on the assumption that it will behave.

## Why — the measurements that do not exist

| Metric required for a publication decision | Value |
|---|---|
| Real model calls | **0** |
| Survival rate | **NOT MEASURED** |
| Composition ratio | **NOT MEASURED** |
| Unsupported assertion rate | **NOT MEASURED** |
| Practical-data rejection rate | **NOT MEASURED** |
| Conflict rejection rate | **NOT MEASURED** |
| Cost per narrative | **NOT MEASURED** |
| Latency | **NOT MEASURED** |

Objective 11 permits publication only when the model shows *"meaningful composition, strong factual grounding, acceptable survival rate, useful narrative, acceptable cost."* Not one of those five has a value. There is nothing to weigh.

## What IS published, and what it is honestly called

Seven narrative blocks across three destinations, every one generated by the **deterministic `rule-based` provider** — a restatement engine that reorders approved claims within a mode's sentence budget. Asserted by test: `all 7 blocks generatedBy=rule-based`, and zero blocks carry `generatedBy: "anthropic"`.

This content is:

- **source-grounded** — every sentence is an approved claim, verified byte-exact against its source
- **not AI-generated**, and never described as such anywhere in the product or documentation
- **useful but not compositional** — composition ratio ~0%, which is what a restatement engine scores by definition

## The credential status

Checked through the project's documented configuration paths only:

```
process.env.ANTHROPIC_API_KEY      unset
process.env.ANTHROPIC_AUTH_TOKEN   unset
.env / .env.local                  no ANTHROPIC entry
```

Pre-flight: `BLOCKED at credential`.

**One gap this phase closed:** `.env.example` never declared `ANTHROPIC_API_KEY`. The project's own configuration documentation did not tell anyone the variable existed. It now does, with a note that the engine falls back to a deterministic extractor and never guesses.

## What would change the decision

Run these two commands. The first costs a handful of tokens and confirms the credential; the second produces every metric above.

```bash
export ANTHROPIC_API_KEY=...
npm run research:evaluate -- --preflight     # confirms the key before spending
npm run research:evaluate -- --live          # 3 destinations x 5 modes
```

Then apply the framework:

| Result | Action |
|---|---|
| **CASE A** — high survival, meaningful composition, acceptable cost | Publish a limited set of verified narratives for the three pilots |
| **CASE B** — high factuality, low composition | Improve claim grouping, narrative planning, prompts, model context. Re-evaluate. **Never the verifier** |
| **CASE C** — poor grounding or frequent violations | Keep AI unpublished. The verified knowledge, timeline, threads and sources remain the production experience |

The thresholds should be set from the first measurement, not guessed now — picking a survival-rate bar before seeing a distribution is how a metric becomes a formality.

## What this decision costs the product

Very little, and that is the point worth making.

The site currently ships **without any model output at all** and is complete: 66 approved facts, 38 timeline entries, 14 connection threads, full source attribution across three destinations, four honest depth states. Phase 8 demonstrated this by removing all narrative and rendering — every destination returned 200 with facts, timeline, threads and sources intact.

**AI is enrichment here, not dependency.** The decision not to publish it is therefore a deferral, not a loss.

## Guarantees that hold regardless of the decision

| Guarantee | Status |
|---|---|
| Unsupported assertions rejected | Verifier 10/10 on required cases; adversarial A–J pass |
| Practical data blocked | Four independent enforcement points |
| Conflicts protected | Excluded at generation input; compromise unverifiable |
| Sikkim curated content untouched | **Now actively defended** — see below |
| Provenance preserved | Every sentence: claimIds, evidenceIds, sourceIds, model, versions |
| Destination isolation | Search scoped; no cross-destination content |
| No paid call on page render | Generation is offline; asserted by test |

### The gap this phase closed

Objective 13 has appeared in several briefs: *if AI contradicts curated Sikkim content, reject or flag — never silently overwrite.* **It had never been implemented.** A research claim asserting a different founding year for a monastery in the curated archive would have been validated on its own evidence and published alongside the curated record, leaving the archive stating two founding dates for one building with nothing marking the disagreement.

`scripts/research/curated-guard.mjs` now parses the 15 curated monastery records and screens every claim. Verified:

- a contradicting founding year is **detected and blocked from publication**
- an agreeing claim is **not** flagged
- *"rebuilt in 1992"* does **not** dispute *"founded in 1966"* — a later event is not a contradiction
- an undated claim cannot contradict a date
- the contradiction is **marked, not deleted** — the curator sees the disagreement and decides

The curated record wins by default for publication because a person verified it against a cited source and the research claim was not. The disagreement is preserved because *"an official portal disagrees with our archive"* is exactly what a curator needs to see.
